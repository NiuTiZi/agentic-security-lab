# 方案文档：Agent 身份与信任安全控制方案

> 本文档描述靶场中已实现并验收的控制方案。安全测试结果见[实验报告总览](05-实验报告总览.md)；
> 方案价值与测试结果分别表述，本文不引用未经本靶场验证的落地经历。

## 1. 场景

企业客服业务：客服员工通过对话式 Agent 为客户查询订单、检索售后资料、发送回访消息；
退款需委托专职退款 Agent 执行。Agent 由真实大模型（DeepSeek 工具调用）驱动，
模型输出的每一次工具调用建议都视为**不可信输入**，必须经统一执行入口核验。

业务主线：员工登录并选择任务 → 确认敏感参数（金额/收件人）→ 可信后台创建任务授权记录 →
Agent 以自身 OAuth 客户端凭据申请访问令牌 → 携带令牌+任务执行凭据调用工具服务 →
工具服务完成六层检查后执行 → 委托退款时生成受限子任务并要求审批 → 全程审计留痕。

## 2. 资产与数据分类

| 资产 | 示例（虚构） | 分类 | 约束 |
| --- | --- | --- | --- |
| 订单与收货信息 | ORD-1001/2001、姓名、地址 | 业务敏感 | 对象级授权：仅归属客服本人可查 |
| 客户联系方式 | 138xxx/139xxx 手机号 | 受限字段 | 禁止原文离开业务边界（不进模型请求原文、不进消息发送原文） |
| 部门售后资料 | dept-east/dept-west 文档 | 部门级 | 检索按部门过滤（第二阶段扩展跨部门实验） |
| 任务授权记录与执行凭据 | task_id + exec_credential | 核心信任凭据 | 可信后台创建，绑定用户/Agent/操作/资源/有效期 |
| OAuth 客户端凭据 | client_id/secret | 核心信任凭据 | 服务端私密配置，不进前端与模型上下文 |

## 3. 信任边界

五方主体、四条边界：

```
[员工用户] --本地账号会话(未来OIDC)--> [可信后台]          ← 边界1：用户身份
[Agent 服务] --OAuth客户端凭据--> [Keycloak授权服务]        ← 边界2：Agent 应用身份
[Agent 服务] --JWT+任务凭据--> [工具服务]                  ← 边界3：应用权限+任务授权
[Agent 服务] --出站适配层--> [DeepSeek模型平台]            ← 边界4：数据出站
```

- **边界1**：用户身份来自可信后台会话核验；请求体中的 user_id/角色等字段是陷阱字段，
  不作为授权依据（AUTH-08）
- **边界2**：Agent 应用身份来自 OAuth 客户端认证；签发的 JWT 不能超出客户端注册 scope
  （Keycloak 对超范围请求整组拒绝）；客户端停用后应用侧同步停用准入
- **边界3**：scope（应用能做什么）+ 任务授权（此刻替谁做哪件事）双重检查；执行凭据由
  可信后台经内部通道推送运行层，模型不能指定或替换（AUTH-12/13）
- **边界4**：所有发往模型平台的内容先经出站适配层——受限字段替换为按任务隔离的占位符；
  消息发送工具另有目的地白名单与参数脱敏（RISK-01/04）

信任锚点：签名私钥仅在 Keycloak；工具服务仅信任固定配置的 JWKS 地址（不接受令牌内 URL）；
任务授权状态在线核验、无跨请求缓存——撤销/停用在下一次调用即生效。

| 用户越权访问（RISK-03） | 客服 A 查客服 B 订单 | 对象级授权：工具服务按任务用户核验归属；对话与直接 HTTP 请求同路径受控 | 工具服务（资源端，非仅网关） | 已实现+验收 |

| 存储与运维泄露（RISK-05） | 日志/备份含敏感字段 | 日志最小化（基础） | 各服务 | 第二阶段 |
| 委托上下文过宽（RISK-06） | 委托消息含无关私密字段 | 最小任务字段（基础） | 运行层 | 第二阶段 |

## 5. 控制机制设计要点

### 5.1 六层调用链与错误码分层

每次工具调用依次经过：客户端认证→令牌签发→JWT 验证→scope 检查→任务与用户授权→业务执行。
失败响应携带失败层与结构化错误码：认证失败 401（missing_token / invalid_signature /
unknown_signing_key / token_expired / audience_mismatch）；授权拒绝 403（insufficient_scope /
task_binding_mismatch / task_revoked / parent_task_revoked / agent_disabled /
object_ownership / order_not_in_scope / recipient_not_in_task / outbound_destination_blocked /
approval_required / delegate_amount_exceeds_parent 等）。根因不掩盖：核验顺序保证返回的是
最深层的真实拒绝原因（如级联撤销的子任务报 parent_task_revoked 而非 task_revoked）。

### 5.2 权限的两个维度

- **应用权限（scope）**：Agent 客户端注册时固定，Keycloak 不签发超出注册的 scope
- **任务授权**：可信后台依据已登录用户确认创建，含允许操作、资源范围、有效期；
  模型建议不能转化为授权——查询任务中提议退款被 operation_not_in_task 拒绝且不产生任何新授权

### 5.3 出站数据控制（独立于模型行为）

出站适配层是发往模型平台与消息工具的唯一通道：受限字段按任务隔离映射为占位符
（‹脱敏手机号#n›），映射不跨任务复用；模型要求"恢复字段"不自动提供原值，恢复仅用于
用户可见回复且接收方为任务用户本人。所有实际出站请求体留存证据（出站观察点），
日常审计仅保留摘要。

### 5.4 撤销与停用的即时性

组件验证发现：Keycloak 停用客户端后，**已签发的未过期令牌验签仍然通过**（签名层不感知
停用状态）。因此设计应用侧在线核验兜底：Agent 停用（两阶段：应用侧+授权服务侧）、任务撤销、
级联撤销均在执行前在线查询最新状态，无缓存——下一次调用即生效。

## 6. 接入位置与改造成本

| 接入点 | 改造内容 | 说明 |
| --- | --- | --- |
| Agent 运行层 | 工具调用统一入口；运行层附加任务上下文；出站适配层 | 模型与工具解耦点，改动集中在运行时，不侵入模型提示词 |
| 工具/资源服务 | JWT 验签、scope 映射、任务授权核验、对象归属、出站控制 | 安全检查在资源端执行，不依赖唯一网关（直接调用同样受控，AUTH-10） |
| 可信后台 | 任务授权记录、审批、撤销、执行凭据发放 | 复用现有用户会话与权限体系，新增任务表与审批表 |
| 授权服务 | 注册 Agent 客户端、scope、audience | 标准组件配置，无定制开发 |

## 7. 责任边界

- **客户（数据 Owner）**：定义数据分类与受限字段清单（本版以虚构手机号为示例标记）；
  出站策略变更需数据 Owner 确认
- **产品（Agent 平台）**：任务确认交互（敏感参数明示）、实验开关管理、证据留存与展示；
  不承担数据分类决策
- **业务系统（订单/客服系统）**：对象归属与业务规则（本版在工具服务实现归属判定）；
  审批人体系
- **安全团队**：信任边界定义、验收口径、防护开关矩阵、实验报告

## 8. 业务影响（本靶场实测口径）

**收益**：防护全开下，合法业务任务 10/10 完成（查询/资料检索/消息发送全链路）；
敏感操作（退款）的确认-审批-受限执行链路完整可用；全程审计可回放。

**成本**：

- 增加等待：用户发起任务需确认敏感参数；退款需审批人介入（预计增加一次人工交互）
- 增加延迟：六层在线核验下，单次工具调用增加的授权核验开销在本地环境不可感知；
  真实模型对话平均 3.5~5.9 秒（模型推理主导）
- 出站脱敏的副作用：模型仅见占位符时无法基于真实手机号生成内容——用户可见回复经权限
  检查后还原，80 次运行中回复还原成功率约 50%（模型有时主动省略该字段），业务可用性未受影响
- 防误报：对象归属检查在合法路径 0 次误拦截（AUTH-11 对照 + LEGIT-PROT 10/10）

**已知失效模式（如实披露）**：单一控制失效时不发生实际外泄——RISK-04 实验中即使模型被
注入诱导提出任务外操作，任务范围检查独立拦截；但若同时关闭全部防护，攻击链前段（获取
客户资料）可完成。纵深防御的必要性由配置对照实验直接证明。

## 9. 边界与后续

- 传输保护：本地回环 HTTP 演示，生产需 TLS 终端与服务间 mTLS（方案预留 HTTPS 配置项）
- OIDC 用户登录：当前本地账号会话，企业 IdP 接入为独立扩展项
- 提示过滤/脱敏覆盖范围：仅虚构标记字段，变体识别（如拆分、编码）为后续能力
- 模型实验结论仅代表 deepseek-flash、temperature=0、各场景 10 次运行范围内的观察；
  更换模型/温度需重新验收
