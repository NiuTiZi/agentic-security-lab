## 1. OAuth 组件行为（Keycloak 26.7.4，独立进程）

| 编号 | 验证项 | 结论 |
| --- | --- | --- |
| V1 | 服务与端点发现 | issuer `http://127.0.0.1:8080/realms/agent-range`；token/JWKS 端点符合 OIDC 常规路径 |
| V2 | 双客户端凭据取令牌 | client_secret_basic 认证，返回 Bearer 令牌，expires_in=300s |
| V3 | JWKS 验签 + iss/aud | RS256；sub 为服务账号 UUID、azp=client_id、scope 如注册、aud 含 `tools-service`（协议映射注入） |
| V4 | 错误客户端密钥 | HTTP 401 unauthorized_client，不签发 |
| V5 | 超范围 scope | **HTTP 400 invalid_scope 整组拒绝**（拒绝而非缩减）——固定为组件预期 |
| V6 | 令牌过期 | ExpiredSignatureError，过期拒绝 |
| V7 | 客户端停用 | 停用后新令牌申请 401；**停用前签发的未过期令牌验签仍通过** → 撤销必须叠加应用侧在线核验 |

V7 是本靶场关键设计输入：仅靠 JWT 验签无法感知授权服务侧状态变化，因此工具服务在验签
之后叠加 Agent 准入状态在线核验（agent_disabled），撤销/停用即时生效。

## 2. 令牌生命周期

- **签发**：Agent 服务以自身客户端凭据（client_credentials，RFC 6749 §4.4）向令牌端点申请；
  不含用户授权环节、不依赖 refresh token
- **有效期**：300 秒（可配置）；过期后 Agent 凭据重新申请
- **载荷最小化**：JWT 仅含身份与授权字段（sub/azp/scope/aud/exp/iat/jti）；
  不写入客户隐私、账号密码或模型平台密钥。JWT 为签名而非加密，载荷可被读取，故按最小化原则装载
- **验证规则**（工具服务执行）：签名+算法白名单（RS256）→ iss → aud（必须含 tools-service）→
  exp/iat → client_id→Agent 可信映射。JWKS 地址来自固定配置，不接受令牌内 URL 指定
- **失效**：自然过期（验签拒绝）或客户端停用（应用侧核验拒绝）；Bearer 令牌自身不可防重放，
  jti 仅用于审计关联

## 3. 任务授权来源

任务授权记录由**可信后台**创建，输入是已登录用户（本地会话核验）在 UI 上明确选择的任务
类型与参数（涉及金额、收件人等敏感参数时强制确认），后台校验该用户业务权限后落库。
记录字段：原始用户、授权 Agent、允许操作（如 order.read / refund.request / message.send）、
资源范围（订单号/收件人白名单）、有效期、状态。

- **模型建议≠授权**：查询任务中模型提议退款 → operation_not_in_task 拒绝，且任务集合不变、
  不产生任何新授权（AUTH-12）
- **任务绑定**：A 的执行凭据配 B 的任务编号 → task_binding_mismatch；A 的会话对 B 任务发起
  对话 → 会话归属核验拒绝（AUTH-13）
- **执行凭据通道**：由后台经内部通道推送 Agent 运行层，不经网页展示、不进模型上下文；
  验收所用凭据经受控测试通道加载，报告仅存脱敏摘要
- **委托链**：客服 Agent 委托时，后台生成受限子任务（绑定订单与金额上限）签发给退款 Agent，
  委托只能收缩权限：子任务金额超父任务确认值 → delegate_amount_exceeds_parent；
  换单 → order_not_in_subtask；提额 → amount_exceeds_limit（审批与授权均不覆盖提额）
- **审批**：approvals 表按子任务+工具+参数绑定；未审批先执行 → approval_required；
  修改金额产生新子任务，旧审批不沿用
- **撤销**：任务撤销在线核验即时生效（task_revoked，非令牌过期）；父任务撤销级联阻断子任务
  执行（parent_task_revoked）

## 5. 凭据盗用实验（CRED-01~04，独立实验客户端真实调用）

| 场景 | 持有材料 | 结果 |
| --- | --- | --- |
| CRED-01 | 仅有效 Agent Bearer 令牌 | 认证层通过（JWT 验签 pass），业务授权拒绝（missing_task_credential）——两层结果分开报告，验证"验签通过≠可执行" |
| CRED-02 | 令牌+有效任务执行凭据 | **范围内查询成功**——如实展示持有者令牌局限：令牌+凭据同时泄露时盗用者可冒用；更换订单/扩大操作仍被拒 |
| CRED-03 | 同 CRED-02，撤销任务后重试 | 任务授权拒绝——失败归因于撤销（在线核验），不是等到令牌自然过期 |
| CRED-04 | 另一有效任务凭据，停用 Agent | 已有令牌调用被拒（agent_disabled）+ 新令牌申请失败（invalid_client）——两阶段停用两侧结果分别记录 |

CRED-02 的"成功"是实验设计的一部分：令牌盗用实验目标是展示能做什么、不能做什么及撤销后的
变化，不预设全部拒绝。未来增加发送方约束令牌（DPoP 类）时再以新对照验证增强效果。

## 6. OAuth、JWT、用户登录与 OIDC 的边界

- **OAuth 2.0**：本项目实现 client_credentials 授权流程（RFC 6749 §4.4），解决**服务端 Agent
  应用**的认证与受限访问范围。该流程不含员工登录、不含员工授权确认，不会自动获得员工权限
- **JWT**：本项目访问令牌的格式（RS256 签名、300s、aud 校验）。采用 JWT ≠ 实现了 OAuth；
  组件实际输出不假定完全符合 RFC 9068 配置文件（以 V1-V7 实测行为为准）
- **用户登录**：本地账号+服务端会话，由可信后台核验用户有效性、部门与数据权限。
  与 Agent 的 OAuth 客户端认证**相互独立**——接入 Agent OAuth 不等于完成用户 OIDC
- **OIDC**：**未实现**。企业/本地标准 OIDC 登录（IdP 对接、ID Token 处理）为后续独立接入项，
  不列为已实现功能

## 7. 已知局限

- 越权对象在演示环境返回明确 403 与错误码（便于定位阻断层）；生产可选择 404 隐藏策略
- 会话令牌与会话管理为本地演示实现，非企业级 IdP 方案
- jti 用于审计关联；本地撤销记录表未做分布式部署验证
- 密钥管理：本机私密配置（.env，已 gitignore）；生产需独立密钥管理服务（第二阶段 RISK-05 范围）
